# UI and responsive QA — 6 September 2026

## Findings and changes

- Tablet attendance and report layouts could grow wider than the viewport.
  The main flex item now shrinks correctly; header actions and class filters wrap.
- Long class names enlarged cards beyond phone widths. Card grid tracks now
  respect available width and class names wrap instead of hiding the name.
- Wide tables retain horizontal scrolling inside their container. A scroll hint
  appears only when needed, and the container supports keyboard focus and arrow
  scrolling with a visible focus ring.
- Selects fit the viewport with long options. Searchable dropdowns share the
  available vertical space between search and a scrollable list, including on
  short screens. Full option names wrap; the closed selection stays compact.
- Dialog headings reserve room for the close button, which has a larger target.
  Long forms scroll within the dynamic viewport and their submit controls remain
  reachable.
- Mobile navigation includes safe-area spacing and an explicit current-page
  announcement. The shorter Attention label distinguishes it from Attendance.
  The selected class workspace tab scrolls into view without moving the page.

## Verification

`npm run test:responsive` runs local Chrome against the actual application
components and routes with isolated API fixtures. It covers 25 application page
states plus a shared-controls fixture at 320, 390, 768 and 1280px. Fixtures include
long academic names and populated academic, people, teaching and attendance
report views, plus empty/error states. Calendar fixtures test layout, not BS/AD
conversion correctness. No college data is read or written.

Additional interaction checks cover:

- Keyboard horizontal table scrolling.
- Pagination and search resetting the offset, and clearing status filters.
- Long select options and compact selected labels.
- Dropdown search and Enter selection, and reaching the last option on a short screen.
- Scrolling long forms to their submit controls at 320 × 568px.

Run with Node 22+ and Chrome; `CHROME_BIN` can override the browser executable.
Screenshots are written to the OS temporary directory as `spas-ui-*.png`.
`QA_INTERACTIONS_ONLY=1 npm run test:responsive` runs just the interaction checks.

Also run `npm run lint`, `npm run build`, and `npm run test:session`.
The existing build advisory about chunks over 500 kB remains.

This pass verifies frontend layout and interactions with controlled data. It is
not a production end-to-end audit, a real-device Safari/Android test, or a formal
accessibility certification. Backend authorization and validation are unchanged.
